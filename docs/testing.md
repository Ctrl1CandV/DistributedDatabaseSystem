# 系统测试交接

用独立的课堂测试库。看 [启动说明](../README.md) 准备环境和 schema。每个场景记录集群规模、启动方式、`node_id`、`term`、`role`、`healthy`、`commit_index`、命令返回码和记录值。节点恢复时保持节点 ID、成员配置及其数据库不变。

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

自动化测试用可控的内存网络隔离节点，覆盖旧主无法提交、分区恢复后修复冲突日志、五节点的多数派边界和预投票开关。若已准备独立 MySQL 测试实例，可设置 `DDB_TEST_MYSQL_PORT`，以及需要的 `DDB_TEST_MYSQL_HOST`、`DDB_TEST_MYSQL_USER`、`DDB_TEST_MYSQL_PASSWORD`，再执行同一命令。该账户需要在测试实例创建和删除临时数据库的权限。集成用例会创建随机命名的库并在结束时删除，验证身份绑定、日志恢复和事务回滚。

部署后的系统验收使用下表。

| 场景 | 操作 | 通过条件 |
| --- | --- | --- |
| 正常读写 | 查任意节点 `status` 获得领导者，写入学号 1001，强一致读，然后删除并再次读 | 写入返回任期和下标，读到新值，删除后返回 `record=null` |
| 跟随者读取 | 写入后等跟随者的提交位置追上，对它执行默认读与 `read 1001 --mode stale` | 默认读提示领导者，本地读返回该节点的记录和提交下标 |
| 换届 | 用独立终端启动三节点，在领导者进程所在终端按 Ctrl+C。查询其余两个节点，再向新领导者提交写入 | 两节点选出新领导者，任期推进，写入成功，原有数据仍可读取 |
| 独立 DB 故障 | 仅停止接在某节点上的 MySQL，保留它的 Python 进程。查看该节点状态，在其余节点继续写入 | 故障节点 `healthy=false`，健康多数可写。数据库重启后该节点 `healthy=true`，提交位置和记录自动追上 |
| 少数派 | 三节点中停止两个，向剩余节点尝试写入和强一致读，再执行本地读 | 写和强一致读失败，本地存储仍健康时允许读取旧的已提交值 |
| 追赶与删除 | 停一个跟随者，在多数派侧更新 1001、删除 1002。使用原配置重启跟随者 | 跟随者本地看到 1001 的新值和 1002 的删除结果，提交位置追上 |
| 五节点容错 | 用五个库部署，停两个节点后写入。再停一个节点尝试写入 | 三个存活时写入继续，两个存活时不确认新写入 |
| 重启后恢复 | 提交记录并等全部副本追上，关闭全部 Python 进程，然后使用原配置与原库重启 | 重新选主，读到之前写入的值，后续写入可以提交 |

### 单独停止或重启节点

本地多开适合快速启动。做逐节点故障验收时，把 `config/node.example.json` 复制成三份 `config/n1.local.json`、`config/n2.local.json`、`config/n3.local.json`。在所有文件填写相同的集群 ID 和成员表，三个 URL 使用 `127.0.0.1:5001`、`127.0.0.1:5002`、`127.0.0.1:5003`（带 `http://`）。分别填写对应的 `node_id`、`bind_port`、`mysql.database`。三份配置的 `bind_host` 都填 `127.0.0.1`。若使用本地启动器已经初始化过的数据库，保持 `cluster_id` 为 `classroom-local`，并使用与启动器一致的节点名和 URL。

在三个终端分别切换到项目目录，设置 `DDB_MYSQL_PASSWORD`，然后执行：

```powershell
.\.venv\Scripts\python.exe -m ddb serve --config config/n1.local.json
```

其他终端分别把文件名改成 `n2.local.json` 和 `n3.local.json`。需要停止哪一个节点，就在对应终端按 Ctrl+C，重启时重复同一条命令。

### 对比预投票和两种读

- 预投票对照使用三台电脑或可独立控制链路的环境。将一个跟随者与另外两个节点双向隔离数秒，保持它自己的 Python/MySQL 可用。先记录该节点和当前领导者的任期，再恢复连接，检查是否触发换届。所有节点分别用默认配置和 `"raft": {"pre_vote": false}` 各做一轮，其余参数保持一致。关闭时孤立节点会重复推进任期，恢复后可能打断原领导者。
- 读模式对照在断连前写入 90 分，断连后在健康多数一侧写成 96 分。多数一侧的强一致读应看到 96。在隔离节点做本地读，若它在断连前已应用 90 分，则可能继续返回 90，且应一并记录它的提交位置。恢复后等待追赶，再比较两侧。

报告可记录故障发生到新领导者首次成功写入的时间，以及恢复节点从启动到读出新数据的时间。同一设置重复几次并记录节点数、数据库是否共享、机器和网络环境。代码提供任期与提交下标，具体耗时由测试现场实测。
